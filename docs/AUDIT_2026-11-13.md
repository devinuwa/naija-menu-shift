# Naija MenuShift — Engineering and product audit
**Date:** 13 November 2026 · **Scope:** GitHub `main` and published Streamlit app · **Evidence levels:** source and automated checks vs. live visual interactions.

## Executive assessment
The app has a credible **research-prototype** architecture, not yet a validated or production-ready food decision product. Keep suya as the first use case rather than hardcoding the product to it. A publicly accessible Streamlit app must retain the fictional-data warning until real serving evidence is reviewed.

## Confirmed strengths
1. Structured ingredient / dish / option / recipe-line inputs with a generic evaluation engine.
2. Beef reference never enters plant recommendations.
3. Hard budget, protein and preparation-time filters; no-feasible-option abstention.
4. Distinct demo vs. evidence-required data directories; research mode fails closed.
5. Traceable source and price-sensitivity displays; keyword vs TF-IDF benchmark scaffold.
6. GitHub Actions lint, tests and CLI smoke tests; latest successful run on prior main at audit start.

## Findings and fixes

| Priority | Area | Evidence / risk | Action |
|---|---|---|---|
| P0 | Public reachability | Repository is private; Streamlit app inherits private access by default, blocking people outside invited developer/viewer lists | Owner: Streamlit Community Cloud → app Settings → Sharing → **This app is public and searchable**. Keep GitHub repository private. Test in signed-out/incognito browser. This is a cloud setting, not a code change. |
| P1 | Allergen constraints | Earlier engine matched only declared labels; incomplete/unknown seasoning label could still be recommended to a user excluding an allergen | This PR abstains for requested allergen exclusions when a recipe includes unknown/unreviewed ingredient labels. Review labels per ingredient; do not claim kitchen cross-contact certification. |
| P1 | Protein score | Existing `min(1, protein/target)` gives identical maximum value to *all* proteins above the hard minimum, so the protein score cannot distinguish feasible options | This PR uses a transparent, bounded, diminishing-returns utility. Food scientists must still validate whether the weights represent meaningful user preference; don't confuse higher grams with nutritional adequacy. |
| P1 | Evidence | Real-source quote tables are present but `data/verified/` is incomplete; raw soybean prices cannot substitute for finished awara price and processing yield | Preserve demo warnings. Require local purchase quotes, dated location, mass balance, true finished servings, ingredient-specific sources, energy/fuel and cooking yield before enabling research-backed ranking. |
| P1 | Input data integrity | Standard DictReader silently accepts duplicate headers, surplus or missing row fields | This PR rejects malformed/ambiguous CSV input. |
| P1 | Recommendation evaluation | Models use TF-IDF + fixed coefficients, not a trained taste or acceptance predictor; existing report shows cases where TF-IDF disagrees with intuitive keyword preference | Pre-register and label independent restaurant/chef scenarios; compare cheapest feasible, keyword overlap and TF-IDF on relevant ranking metrics. Do not call the model state-of-the-art without independent evidence. |
| P2 | UI and information hierarchy | Source contains a large multi-tab dashboard and wide data tables; mobile reflow, first-use guidance, keyboard navigation and contrast are **unverified**, not proven defects | Test signed-out public experience at 390 px and desktop; verify 200% zoom, keyboard focus, screen-reader labels, long tables and no-feasible states; use screenshots before visual redesign. |
| P2 | App availability | App title and management control were visible to a connected authenticated browser, but full public render was not captured or interacted with | Owner sets public sharing; then audit a complete flow with screenshots and an incognito nonmember. |
| P2 | Dependencies/operations | Dependencies are lower/upper bounded in pyproject.toml, no lockfile; upgrades may affect behaviour | Continue controlled Dependabot/CI and verified releases; do not add external services or secret keys unless justified. |
| P2 | Privacy | Public app exposes source tables and synthetic figures via its UI. Keep collaborator contact information and unpublished private research out of view before making public | Review public-facing content and disclosure; keep raw code in private GitHub repository. |
